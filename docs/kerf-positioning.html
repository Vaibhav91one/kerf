Kerf/market research /11 August 2026

You are not first to this market. You are first to the right metric.

Three products already rank Claude Code users on a public leaderboard. All three rank on tokens burned or dollars spent — and that metric is, right now, being publicly torn apart by the engineering press. Kerf ranks on whether the edits stuck. That is the whole pitch, and nothing on the site currently says it.

The finding

Your competitors' core metric became a liability in the same year you built the alternative.

Viberank, CCgather and claudeusage are direct competitors: same audience, same CLI-sync onboarding, same public board. Every one of them ranks people by cost or token count. In 2026 that practice acquired a name — tokenmaxxing — and a backlash. Meta ran an internal token leaderboard, then dismantled it after the coverage. The Pragmatic Engineer, LeadDev and CIO have all run pieces arguing token count is the lines-of-code metric of the AI era. Engineers have admitted to burning tokens deliberately to avoid looking like light AI users.

Kerf's scoring model — precision, landed edits, a daily cap, sublinear volume — is the structural answer to exactly that critique. You did not build it as a rebuttal, but it is one. Lead with it. "The leaderboard that doesn't reward burning tokens" is a positioning nobody else in this category can take, because taking it would invalidate their own board.

Where onboarding actually loses people

Benchmark for developer tools is under 15 minutes from signup to first value, and the strongest products land it in under two. Ranked by how much each one costs you.

InstallBlocking

There is no npx kerf, and all three competitors have one.

Kerf installs today as a two-line wrapper in ~/.local/bin with the repo path hardcoded — it cannot be handed to a stranger at all. This is the single largest gap on this page and it invalidates every promotion tactic below it: there is no point posting to Show HN if the first instruction is "clone this monorepo".

The blocker is real (workspace:* and Node's refusal to strip types inside node_modules), but it is a packaging problem, not a design one — bundle the CLI and its one shared dependency into a single published artifact and the constraint disappears. Nothing else ships until this does.

IdentityHigh

Clerk is right; Google-only is not.

Social login lifts signup conversion 20–35%, so Clerk is the correct call. But this audience's native identity is GitHub — Viberank uses it specifically as the verification signal, and a GitHub handle is what makes a profile worth linking to. Clerk supports it as a configuration change, not a rewrite. Add GitHub alongside Google and pull the avatar and handle from it.

First valueHigh

Nothing happens until the user runs three commands.

Sign in, install, kerf login, kerf sync — four steps before the first number appears. Every competitor is one npx away from a rank. The fix is not a tour; it is collapsing the chain: one command that syncs and opens the browser already signed in, with the sync running before the account exists and attaching on login.

Empty stateCheap fix

A signed-out visitor cannot see what a good profile looks like.

Public-first is a real advantage — the competitors gate less than you might think, and you gate almost nothing. Spend it: make one exemplary public profile the thing a first-time visitor lands on, and let them see a filled-in season board before being asked for anything.

The growth loop you are missing

WakaTime's durable growth mechanic is not its leaderboard. It is the embeddable card: a badge or stats block a developer pastes into a GitHub profile README, which then advertises the product to every visitor of that repo, forever, with no ongoing effort from either party. Achievement badges have been measured driving triple-digit lifts in referrals for precisely this reason — a badge is social proof its owner distributes for you.

Kerf has the assets for this already and does not expose them. You have league crests, badge artwork with squared viewboxes, a rank, a streak, and a points total. Three artifacts, in order of leverage:

  • A README SVG card at a stable URL per handle — crest, level, points, streak. This is the one that compounds.
  • A share image per season for the profile and for social — the Wrapped mechanic, but continuous rather than annual.
  • Project pages as the public artifact — you already render GitHub facts, activity and language mix. That page is linkable in a repo README on its own merit, which pulls in people who never intended to join a league.
Sequencing The card only works once the profile it links to is worth landing on, and only once a stranger can install the CLI. It is the highest-leverage item on this page and the third one to build.

Where to promote it

For a CLI-shaped open-source developer tool the consensus ordering is unambiguous: Show HN first, everything else supporting. A 2026 launch is a coordinated push across several surfaces in one week, not a single post. This is a sequence, so it is ordered as one.

Before

Publish the CLI and get 30–50 real profiles on the board.

An empty leaderboard is the one thing a launch cannot survive — the product is the people on it. Seed from the communities you are already in before any public post.

Day 1

Show HN — and lead with the metric argument, not the product.

The title carries the whole thing. Something in the shape of a leaderboard for coding agents that deliberately does not rank on tokens, with the tokenmaxxing critique as the reason. That framing is an argument HN already cares about; "another Claude Code leaderboard" is not. Be in the thread all day.

Day 1–2

The subreddits where this audience already sits.

r/ClaudeAI and the adjacent agent-tooling subs are where the three competitors found their first users. Post the metric argument, not a launch announcement — these communities reject the latter and reward the former.

Week 1

Product Hunt, DevHunt, and the awesome lists.

DevHunt is specifically for dev tools and runs weekly, so momentum accumulates instead of evaporating at midnight. Product Hunt is worth it for reach — CCgather's launch there is public and modest, which tells you the bar. Awesome-list PRs and GitHub trending do more for an open-source project than any launch feed.

Ongoing

One community space, not five.

The 2026 pattern is developers spread across five platforms and present on none. Pick two channels and work them consistently. For an open-source project that usually means GitHub Discussions plus one chat space — and Kerf has an unusual option here, because it ships its own chat and live feed. Making your own product the community venue is coherent with what it is.

Two traps, one of which you have already avoided

Trap Streaks get gamed, and the gaming looks like success. Duolingo found users doing 30 seconds of nothing to keep a streak alive; GitHub's contribution graph produces daily commits that exist only to fill a square. Kerf's daily point cap and non-qualifying-session floor already counter this — which is a genuine design advantage, and it is currently explained nowhere a visitor will read it. Put the reasoning on the season page.
Watch The privacy story is a marketing asset you are underselling. Competitors say prompts never leave your machine. You enforce it structurally — a schema-walking validator that rejects any free-text field, no event table, per-item visibility. That is a stronger claim than theirs and it is a paragraph on a sub-page. For an audience currently nervous about what agent tooling uploads, it belongs on the landing surface.
